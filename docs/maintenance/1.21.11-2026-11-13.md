# Folia 1.21.11 维护记录（2026-11-13）

维护分支：catserver/1.21.11。原始基线：3ef0ba66b20599d24f235ac795865047c29c5eb4。
Paper 基线：79c77f5d7d409b692b67f75e03e5c138a9283fad；Java 21。

本批按先前审计落地可限定范围的修复，不代表所有开放 issue 都已修复，也不代表已测得 MSPT 改善。上游 issue/PR 是来源线索，不等于上游已经认可或合入本分支方案。

## 本批实现与提交解释

| 问题 | 改动与理由 | 验证边界 |
| --- | --- | --- |
| PR #459 首次自动保存 | 登录登记后初始化 lastSave；先识别 LAST_SAVE_ABSENT，再计算 nanoTime 差值。保留强制保存、所属线程检查和每 tick 限额。 | 生产保存判定的 5 项回归覆盖未保存、完整间隔、负 nanoTime、回绕和强制保存。实际 playerdata 落盘/重启仍需隔离服验收。 |

| #406 实体可见性 | 每玩家同一把锁保护 Map、内部插件 Set 和 first/last 复合判断；静态插件弱引用缓存单独加锁且不嵌套。tracker、发包及插件事件在锁外。 | 5 项回归覆盖多插件、旧 API 的 null 插件、默认不可见、并发添加/删除、实体移除与读取。完整 hide/show API 仍受线程归属限制。 |
| #438 珍珠伤害来源 | 延迟传送后伤害事件携带珍珠引用，不再错误地把受伤玩家自己当作 damager；回调不读取珍珠状态。 | 编译及静态路径审查；插件 EntityDamageByEntityEvent 监听仍需实服验收。 |
| #421 珍珠与维度切换 | 死亡清除逻辑排除 CHANGED_DIMENSION 临时移除；保留原有真实死亡和 gamerule 条件。 | 编译及静态路径审查；真实死亡、跨维窗口、退出和卸载需要分别回归。 |
| #441 teleportAsync flags | 调度前转换并冻结相对速度 flags；在实体所属线程调用既有 TeleportTransition overload 计算绝对速度。位置保持绝对坐标。 | 8 组实际 CraftEntity → NMS overload 调用链测试，核对轴、旋转、cause、内部 flags、future 和不可变集合。乘客/玩家跨维运行测试尚待完成。 |
| #431 村民初始化 | 活动/记忆注册仍立即完成；未入世界或非 owner 时仅推迟环境/时刻采样，至首个 active/inactive AI step。已生效 owner 的 refreshBrain 仍立即采样。 | 编译及两人源码审查。pending 字段不能有 initializer，否则会覆盖 superclass 构造期间 makeBrain 设置。NoAI 时保持 pending，启用 AI 后才处理。 |
| #427、PR #504 末影龙部件 | 在 region/tracking callbacks 前和异步维度复制 transform 后把部件同步到龙的中心，避免仍滞留原点。 | 3 项回归使用真实部件验证远坐标、chunk/AABB、重复移动和复制 transform 顺序。部件临时集中在中心，首 AI tick 才重算姿态；不保证前置 spawn 事件已看到准确部件，也未完成真实区域追踪验证。 |

每个逻辑修复保留独立 feature patch，patch 头和 Git commit body 说明来源、实现原因与限制。Minecraft 源码和 paper-server 均是生成目录；维护时修改源码、提交到各自生成 Git，再用 paperweight 重建受版本控制的 patch，不要只保留生成源码改动。

## 明确延后

- PR #498 资源刷新、PR #496 criterion：旧版 scheduler API 不同，需要逐调用点在 owner 线程读取状态和传递不可变参数，未机械复制新版大改动。
- 红石/GameEvent 的后续上游 95c3f27：两处越区 continue 会丢弃传播，不是跨区转发。需要边界行为测试；Turbo 的早期读取和实验红石也不因此自动闭合。
- #490 / #330 通用可取消传送事件：需要预检、目标重定向、回滚、乘客和 exactly-once 完成设计，未补一个不完整事件调用。
- #353 停机顺序：涉及数据安全，未随意调整插件/区域停止顺序。
- #454 / #520 网络卡死/攻击报告：缺少当前无插件复现，未当作已证实漏洞修改协议。
- #437 / #447、#531 调度公平、#469 跨维农场背压：需线程栈及固定负载测量，不做推测性全局调度改造。
- #505/#506 特定新版地图存储回归不匹配当前 1.21.11；#435 也已报告为 Vanilla/Paper 行为，不列为本批 Folia 修复。

## 上线前隔离服验收

1. 固定插件/地图/Java 参数，开启多个相隔较远的活跃区域；对比区域 MSPT、长尾 tick、区块生成、实体量和磁盘，而不只看 TPS。
2. 确认首次周期保存、max-per-tick、正常退出、强制保存及重启后玩家数据；不要用生产地图进行强杀试验。
3. 多插件隐藏/显示同一实体，跨区移动、传送、卸载、退出及重新进入；核对客户端追踪和引用语义。
4. 珍珠真实死亡、跨维、退出、卸载、gamerule true/false；监听 damager，检查回调失败处理和玩家数据。
5. 玩家/实体各速度 flag 组合、同区/跨区/跨世界、带乘客和失败情况；验证实际使用的传送限制插件。
6. 村民不同职业/年龄、active/inactive/NoAI 切换及双向跨维；确认日程、POI、交易、记忆和保存恢复。
7. 远离原点生成、冷加载及跨维传送末影龙，检查首 tick、NoAI、各部件命中框和追踪。MiniHUD 的服务端 debug 订阅被主动禁用是本批已知功能变化。
